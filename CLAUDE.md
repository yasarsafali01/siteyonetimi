## Mimari kararları
- **Backend:** Go + Gin + pgx/v5 + PostgreSQL (NestJS değil — kullanıcı önceliği düşük sunucu maliyeti + güvenlik + performans, Go bu üç kritere göre seçildi).
- **Web:** React + TypeScript + MUI v9 + Vite. **Dikkat:** MUI v9'da `p`/`mb`/`display` gibi stil kısayolları Box/Typography üzerinde doğrudan prop olarak çalışmıyor — `sx={{...}}` kullanılmalı.
- **Mobil:** Expo SDK 57 (React Native 0.86) + TypeScript, `expo-router` ile dosya tabanlı routing. **Dikkat:** `@react-native-async-storage/async-storage` mutlaka Expo'nun o SDK için beklediği sürümde kalmalı (`npx expo install --check` ile doğrula) — SDK 57 için beklenen sürüm **2.2.0** ve bu sürümün API'si `multiSet`/`multiRemove` kullanıyor (v3'teki `setMany`/`removeMany` değil). 2026-09-03'te paket yanlışlıkla 3.1.1'e yükseltilmiş bulundu; bu, Expo Go'da native modülün JS tarafıyla eşleşmemesine ve "AsyncStorageError: Native module is null, cannot access legacy storage" hatasıyla uygulamanın açılış ekranında sonsuz spinner'da kalmasına yol açıyordu — 2.2.0'a düşürülüp `src/api/client.ts` v2 API'sine çevrilerek düzeltildi, Android emülatöründe (Pixel_4_XL AVD) uçtan uca doğrulandı.
- **Portlar** (bu makinede native servisler 5432/8080'i işgal ettiği için): Postgres host portu **55432**, backend API **8081**, frontend **5173'e sabitlendi (2026-09-02)** — `vite.config.ts`'de `server.port: 5173, strictPort: true` eklendi, artık başka bir şey 5173'ü tutuyorsa Vite hata verip durur, sessizce başka porta kaymaz. (Daha önce birden fazla `npm run dev` art arda başlatılıp eskileri kapatılmadığı için 5173/5174/5175'te aynı anda 3 zombi sunucu birikmişti — bu kafa karışıklığının kaynağıydı. Yeni bir `npm run dev` başlatmadan önce her zaman eski `node`/Vite süreçlerini kapat.) `docker-compose.yml` ve `backend/internal/config/config.go` içinde belgeli.
- **Migration:** `backend/migrations/*.sql` elle yazılıyor, `docker exec -i siteyonetimi-postgres-1 psql -U postgres -d siteyonetimi < dosya.sql` ile uygulanıyor (golang-migrate CLI kurulu değil, sadece kütüphane bağımlılığı var).
- `go mod tidy` bu makinede GOPATH kökündeki ilgisiz bir `go.mod` yüzünden hatalı "go.mod bulunamadı" hatası veriyor. Bunun yerine `go build ./...` / `go vet ./...` ile doğrula, bağımlılık eklemek için `go get <paket>` kullan.
- Auth/RBAC temel altyapısı hazır: `internal/auth`, `internal/rbac`, `internal/middleware`. Yeni her modül kendi `internal/<modül>` paketinde model+service+handler olarak eklenir, `httpserver/server.go`'ya route'ları kaydedilir.
- **Kalabalık sayfa dekomposisyonu + gelir/gider grafiği (2026-09-02):** Sakin Paneli tek uzun sayfaydı, `pages/resident/` altında 5 ayrı sidebar rotasına bölündü — `ResidentLayout.tsx` (AppShell + `ResidentContext` ile `me`/`activeResidency` paylaşımı, birden fazla birimi olan sakin için header'da birim seçici), `ResidentOverviewPage` (istatistik kartları), `ResidentDebtsPage`, `ResidentRequestsPage`, `ResidentReservationsPage`, `ResidentInvitationsPage`. `PersonDetailPage` ve `EmployeeDetailPage` de benzer şekilde kalabalıktı — MUI `Tabs` ile bölümlere ayrıldı (sidebar değil, çünkü bunlar bir üst listenin "detay" sayfaları — sidebar yerine sekme daha doğru desen). Site "Genel Bakış" sayfasına (`SiteDetailPage.tsx`) istatistik kartları (açık borç, bu ay tahsilat, açık talep, bekleyen rezervasyon — `internal/reporting`'in dashboard endpoint'i) ve **gelir/gider grafiği** eklendi: yeni backend endpoint'i `GET /sites/:siteId/reports/monthly-income-expense` (`internal/accounting`, journal_entries üzerinden ay bazlı gelir/gider kırılımı), frontend'de sıfırdan yazılmış `components/IncomeExpenseChart.tsx` (SVG grouped bar chart — dataviz skill'i takip edilerek: kategorik renk (mavi `#2a78d6` gelir / turuncu `#eb6834` gider, `validate_palette.js` ile CVD-güvenli doğrulandı), 24px'i geçmeyen 4px yuvarlak köşeli barlar, hairline gridline, per-bar hover tooltip, legend). Dış kütüphane eklenmedi (recharts vb.) — küçük veri setleri için el yazımı SVG yeterli. **Kural:** Yeni bir grafik eklerken önce `dataviz` skill'ini yükle, mevcut `IncomeExpenseChart.tsx`'teki renk/mark spec'lerini örnek al.
- **Tasarım sistemi (2026-09-02 eklendi):** `frontend/src/theme.ts` (MUI `createTheme` — indigo `#4f46e5` ana renk, `shape.borderRadius: 10`, düz/gölgesiz `AppBar`/`Card`, `textTransform:none` butonlar) `main.tsx`'te `ThemeProvider` ile sarmalanıyor. Tüm giriş yapmış kullanıcı sayfaları artık ortak `frontend/src/components/AppShell.tsx` bileşenini kullanıyor — responsive sol sidebar (masaüstünde sabit `Drawer`, mobilde hamburger ile açılan `temporary Drawer`), ikonlu nav listesi (`@mui/icons-material`), alt kısımda kullanıcı avatarı+rol chip'i+çıkış butonu. Üç kullanım yeri: `MainLayout.tsx` (üst seviye: Anasayfa/Siteler/Kişiler/Kullanıcılar), `SiteLayout.tsx` (site içi 19 modül, ikonlu), `ResidentDashboardPage.tsx` (sakin paneli, tek nav item). **Kural:** Yeni bir sayfa eklerken kendi `AppBar`/`Toolbar` yazma — ya var olan bir layout'un (`MainLayout`/`SiteLayout`) altına route olarak ekle (o zaman sayfa sade `<Box sx={{p:4}}>...</Box>` döner), ya da tek başına bir sayfaysa (`ResidentDashboardPage` gibi) doğrudan `<AppShell title=... navItems=...>` ile sarmala. MUI v9 notu: `ListItemText`'te `primaryTypographyProps` kaldırılmış, `slotProps={{primary:{...}}}` kullan; `Typography`'de `fontWeight` gibi propları doğrudan değil `sx={{fontWeight:...}}` ile ver — bunlar sadece `npm run build` (`tsc -b`) ile yakalanıyor, `npx tsc --noEmit` bazen atlıyor, o yüzden frontend değişikliklerini doğrularken `npm run build` tercih et.

## Site Sakini (Sakin) Paneli — web (2026-09-02 eklendi)
Kat maliki/kiracı hesapları artık web'de kendi ayrı panelinde çalışıyor (mobil değil — mobil hâlâ sadece iskelet, modül 24 kapsamına ertelendi, ama sakin ihtiyacı web'de karşılandı). Backend: `GET /api/v1/auth/me` (yeni, `internal/auth`) oturumdaki kullanıcının kimliğini + (sakin ise) bağlı `persons` kaydını + `unit_residents` üzerinden malik/kiracı olduğu birim(ler)i site/blok bağlamıyla tek çağrıda döner. Web: `LoginPage` girişten sonra `utype` claim'ine göre yönlendiriyor (`yonetici` → `/dashboard`, `sakin` → `/resident`); `ProtectedRoute` sakin hesabının URL ile admin rotalarına gitmesini engelleyip `/resident`'a yönlendiriyor. Yeni `ResidentDashboardPage.tsx`: bakiye özeti + borç detay tablosu (`GetPersonBalance`/`ListChargesForUnit`), Taleplerim (liste + yeni talep — backend zaten unitId/reportedBy'ı otomatik dolduruyor), Rezervasyonlarım (liste, client-side kendi birimine filtrelenir + yeni rezervasyon), Ziyaretçi Davetiyelerim (liste + yeni davetiye). Birden fazla bağımsız bölümü olan bir sakin için üstte bölüm seçici var. Uçtan uca curl ile doğrulandı — sayfanın yapacağı tüm çağrılar (`/auth/me`, bakiye, borçlar, talepler, rezervasyonlar, ortak alanlar, davetiyeler) test edildi. **Not:** `npx tsc --noEmit` proje referanslarını (`tsc -b`'nin kullandığı) atlayabiliyor — bir hata (SurveysPage'te `Typography fontWeight` prop'u) sadece `npm run build` ile yakalandı ve düzeltildi; bundan sonra frontend değişikliklerini doğrularken `npm run build` tercih edilmeli, sadece `tsc --noEmit` yeterli olmayabilir.
